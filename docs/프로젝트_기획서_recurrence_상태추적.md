# Recurrence가 상태 추적(State Tracking)에 주는 이점 검증
## — Universal Transformer vs 일반 트랜스포머 비교 실험

> 토이 프로젝트 기획서 draft v1

---

## 1. 한 줄 요약

동일 조건(파라미터 규모, 데이터, 학습 방식)에서 **recurrent 구조(Universal Transformer)** 와 **일반 트랜스포머**를, 자연어로 서술된 **상태 추적(state tracking) 과제**에서 비교하여, recurrence가 상태 추적과 그 길이 일반화(length generalization)에 실제로 이점을 주는지 검증한다.

---

## 2. 문제의식

### 2.1 출발점

최근 이론 연구(Merrill & Sabharwal 등)는 표준 트랜스포머가 계산복잡도 클래스 **TC⁰** 안에 갇혀 있어, 상태를 순차적으로 갱신·추적해야 하는 문제(state tracking)를 원리적으로 잘 풀지 못한다는 것을 보인다. 반면 **recurrent 구조**(입력에 따라 늘어나는 직렬 recurrence를 갖는 모델)는 이런 한계에서 자유롭다.

실무에서 트랜스포머가 이 한계를 우회하는 대표적인 방법이 **Chain-of-Thought(CoT)** 다. CoT는 중간 결과를 토큰으로 생성하고 다시 입력받는 방식으로, recurrence를 **토큰 공간(시간축)에 외재화**하여 표현력을 확장한다(이 역시 최근 이론 연구로 정식화됨). 그러나 이는 토큰 생성 비용이 크다는 단점이 있다.

이 지점에서 다음 질문이 자연스럽게 따라온다:

> **모델 내부에 recurrence를 직접 내장하면(Universal Transformer 등), CoT 없이도 상태 추적 능력을 얻을 수 있는가? 그렇다면 그 이점은 얼마나 되는가?**

### 2.2 왜 NLP 태스크인가 — 예상되는 반박과 대응

이 주제는 계산이론·아키텍처 비교에 가까워 보일 수 있어, "이게 자연어처리 태스크가 맞느냐"는 문제제기가 나올 수 있다. 이에 대한 대응 방향은 다음과 같다.

- **입력을 자연어 서사로 구성한다.** 순수 기호열(symbol sequence)이 아니라, "OO가 OO를 가지고 있다", "OO와 OO가 교환했다"와 같은 자연어 문장으로 상태 변화를 서술하고, 모델은 이 서사를 읽어 최종 상태를 추론한다.
- **선례가 있는 문제 설정이다.** 이런 형태의 "자연어 서사 속 상태·관계 추적"은 NLP 학계에서 이미 확립된 문제 유형이다.
  - **CLUTRR** (Sinha et al., 2019): 가족관계 서사에서 여러 단계의 관계를 합성해 추론
  - **SCONE** (Long, Pasupat & Liang, 2016): 자연어 지시문을 따라가며 world state를 갱신
  - **Tracking Shuffled Objects** (BIG-Bench / BIG-Bench Hard, Suzgun et al., 2022): 여러 인물이 물건을 주고받는 서사 속에서 최종적으로 누가 무엇을 가지고 있는지 추론 — 본 프로젝트가 채택한 형식의 직접적 선례
- **구조화된 출력을 요구하는 것도 NLP에서 이례적이지 않다.** Slot-filling, 개체명 인식(NER), 시퀀스 라벨링 등 "자연어 입력 → 구조화된 출력"은 표준적인 NLP 태스크 유형이다.

---

## 3. 연구 질문 및 가설

**RQ**: 자연어로 서술된 상태 추적 과제에서, recurrent 구조(Universal Transformer)는 일반 트랜스포머보다 (1) 정확도, (2) 특히 학습 시 접하지 못한 긴 서사에 대한 일반화(length generalization) 측면에서 우위를 보이는가?

**가설**: Universal Transformer는 학습 범위 내 성능은 일반 트랜스포머와 비슷하거나 근소하게 우세하지만, 학습 범위를 벗어난 긴 서사(더 많은 상태 변화 이벤트)에서는 일반 트랜스포머보다 뚜렷하게 우수한 일반화 성능을 보일 것이다.

---

## 4. 실험 설계

### 4.1 태스크 형식

Tracking Shuffled Objects 스타일의 **자체 생성 데이터셋**을 사용한다. N명의 인물이 각자 다른 아이템(예: 색깔 공)을 하나씩 가진 상태에서 출발해, 여러 차례의 **쌍끼리 교환(pairwise swap)** 이벤트를 자연어 문장으로 서술받고, 모든 교환이 끝난 뒤 각 인물이 최종적으로 무엇을 가지고 있는지를 예측한다.

```
초기 배정: "Alice는 red를, Bob은 blue를, Carol은 green을, ... 가지고 있다."
이벤트열: "Alice와 Bob이 교환했다. Carol과 Alice가 교환했다. ..."
질의/출력: 각 인물이 최종적으로 무엇을 가지고 있는가 (전체 상태 예측)
```

기존 벤치마크(CLUTRR 등)를 그대로 쓰지 않고 직접 생성기를 구축하는 이유:

- 데이터 생성을 절차적으로 통제할 수 있어, **학습/평가 시 스왑 횟수(서사 길이)를 자유롭게 조절**할 수 있다 (length generalization 프로토콜에 필수).
- Vocab을 최소로 유지해 "모델이 다양한 표면형을 처리하는 능력"이 아니라 **순수하게 순차적 상태 합성 능력**을 측정하는 데 집중할 수 있다.

### 4.2 데이터 설계

| 항목 | 설정 |
|---|---|
| 인물/아이템 수 (N) | 5 |
| Vocab | 인물 이름 5개 + 아이템 이름 5개 + 최소 기능어(교환, 은/는, 가지고 있다 등) + 슬롯 쿼리 토큰 5개 — 20~30 토큰 내외로 고정 |
| 조합 생성 | 이름/아이템 풀은 고정, 초기 배정과 교환 시퀀스는 매 예제마다 무작위 생성 (암기 방지) |
| 스왑 방식 | 임의의 두 인물 간 쌍 교환 (인접 제한 없음) |
| 학습 시퀀스 길이 | 스왑 횟수 2 ~ L_train (예: 10) 사이 무작위 |
| 평가 — ID | 학습과 동일 범위 |
| 평가 — OOD (길이 일반화) | L_train의 4~8배 (예: 40~80회 스왑) |
| Supervision | 최종 상태만 (메인 비교) |

### 4.3 비교 모델

두 모델 모두 **사전학습 없이 from-scratch로 학습**한다 (임베딩, 토크나이저 포함 전부 자체 구축). 이는 "recurrence 유무"라는 변수 하나만 다르고 그 외 조건(vocab, 임베딩 차원, 초기화, 데이터)을 동일하게 유지하기 위함이다.

| | 모델 A — 일반 트랜스포머 | 모델 B — Universal Transformer |
|---|---|---|
| 구조 | 레이어별 독립 가중치, 고정 깊이 | 블록 하나를 파라미터 공유하여 T회 반복 |
| Recurrence | 없음 (1회 forward pass) | 있음 (latent 공간에서 반복 갱신) |
| 규모 | hidden_dim 128, 4 head, 소규모 | 동일 조건으로 맞춤 |

### 4.4 출력 구조

각 인물 이름에 대응하는 **슬롯 쿼리 토큰**(예: `SLOT_Alice`)을 입력 시퀀스 끝에 추가하고, 해당 위치의 출력 hidden state를 **공유 MLP 분류기** 하나에 통과시켜 "그 인물이 최종적으로 무엇을 가지고 있는가"를 N-way 분류로 예측한다. (슬롯마다 별도 분류기를 두지 않고 하나의 분류기를 재사용 — 시퀀스 라벨링의 표준적인 패턴.)

Causal attention 특성상, 슬롯 토큰은 시퀀스 맨 끝에 위치해 서사 전체(모든 교환 이벤트)를 참고할 수 있다.

### 4.5 평가 지표

- **전체 상태 정확도**: N개 슬롯을 모두 맞춘 비율
- **슬롯별 평균 정확도**: 개별 슬롯 예측 정확도의 평균
- **스왑 횟수(서사 길이)별 정확도 곡선**: ID 구간과 OOD 구간을 나누어, 길이가 늘어남에 따라 두 모델의 성능이 어떻게 달라지는지 비교 (본 연구의 핵심 결과물)

## 5. 확장 실험 (시간·리소스 허용 시)

메인 비교(A vs B)를 우선 완료한 뒤, 여유가 있을 경우 아래를 추가한다. 매 스왑 시점의 상태를 라벨로 남겨두면 두 확장 실험에서 공통으로 재사용할 수 있어 인프라 효율적이다.

- **B′ — Deep Supervision**: Universal Transformer의 각 반복(iteration)마다 그 시점까지의 상태를 supervision으로 추가 (반복 스텝 = 시간 스텝이라는 자연스러운 대응 활용).
- **C — CoT를 적용한 일반 트랜스포머**: 매 스왑마다 중간 상태를 명시적으로 생성하도록 teacher forcing으로 학습. Recurrence를 토큰 공간에 외재화하는 조건으로, "recurrence를 latent에 내장(B)" vs "텍스트로 외재화(C)"의 비교가 가능해짐.

이 확장까지 포함하면 아래 4개 조건이 완성된다.

| 조건 | recurrence 위치 |
|---|---|
| A. 일반 트랜스포머 | 없음 |
| B. Universal Transformer | latent 공간 (내장) |
| C. 일반 트랜스포머 + CoT | 토큰 공간 (외재화) |

---

## 6. 기대 결과 및 의의

- A와 B가 ID 구간에서는 유사하지만 OOD(긴 서사)에서 B가 뚜렷이 우세하다면, **recurrence가 상태 추적의 길이 일반화에 실질적 이점을 준다**는 것을 자연어 과제에서 직접 보이는 결과가 된다.
- 확장 실험까지 진행되면, "recurrence를 어디에 두는가(latent 내장 vs 토큰 외재화)"에 따른 성능·비용 트레이드오프까지 비교할 수 있어, 최근 LLM 추론 능력 향상 방법론(CoT, looped/recurrent transformer)에 대한 실증적 논의로 이어질 수 있다.
